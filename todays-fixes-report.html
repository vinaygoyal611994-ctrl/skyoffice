Design & Visual
1
Terms & Privacy pages looked plain and unprofessional
Problem
The Terms of Use and Privacy Policy pages had a simple white background with plain text and basic headings. There was no visual structure — it looked like an unformatted document, not part of a professional platform.
Fixed
Both pages were redesigned to match the app theme: light grey background, a white card with a thin primary colour strip at the top, "SKAYOFFICE · LEGAL" label, bold page title, numbered section badges, custom bullet points, and a clean footer row.
2
404 "Page Not Found" page looked like a plain error message
Problem
The 404 error page showed only a large bold "404" number and a plain text message. It had no icon, no visual hierarchy, and did not feel like part of the SkayOffice product — it looked like a developer placeholder.
Fixed
The page now has a branded icon badge (search icon in a rounded square), a large ghost-style "404" watermark in a soft colour, a bold title, a readable description, and a properly styled "Back to Home" button — all consistent with the app design.
3
Footer looked basic with no visual hierarchy
Problem
The website footer had plain column headings, no visual separation at the top, basic contact links with no icons, and a cluttered copyright bar. It did not feel like a finished, professional footer.
Fixed
Footer now has a thin primary colour accent strip at the very top, column headings styled as small uppercase labels, contact links with icon badges that highlight on hover, and a cleaner copyright bar — matching the professional look of the rest of the site.

Usability & User Experience
1
Reset Password page had no star (*) on the required email field
Problem
The "Reset Password" page showed an Email Address field with no indication that it is required. Users could not tell at a glance what they must fill in — inconsistent with the Login and Register pages which already have the star indicator.
Fixed
A red star (*) now appears next to the Email Address label. A small "* Required fields" note was also added below the Submit button — matching the standard used on Login and Register pages for consistency.
2
"Back to Login" on Reset Password page looked like plain text, not a button
Problem
The "Back to Login" link at the bottom of the Reset Password page was styled as plain underlined text. It did not look clickable or stand out as a navigation action — unlike every other secondary action in the app which has a proper button or bordered link style.
Fixed
The link is now styled as a proper bordered button with a back-arrow icon, hover background effect, and the correct font weight — consistent with secondary navigation actions across the rest of the app. Also supports right-to-left (Arabic) direction automatically.
3
Voice search popup opened in the top-left corner of the screen
Problem
When a user clicked the microphone button, the voice search popup window opened at the top-left corner of the screen. This felt jarring and unpredictable — users had to look for the popup rather than finding it naturally in front of them.
Fixed
The popup now calculates the centre of the user's screen and opens directly in the middle of the window — a smooth, expected behaviour matching how other browser popups (like payment dialogs and OAuth windows) appear.
4
Terms & Privacy page design clashed with the app theme
Problem
After the first redesign of the Terms and Privacy pages, the header section used a dark navy/blue gradient background. This looked completely different from the rest of the app, which uses a clean light grey and white card style throughout.
Fixed
The dark gradient header was removed and replaced with a light, card-based layout that perfectly matches the app's existing Login and Register page style — same background colour, same card shape, same rounded corners.
5
Home page hero section background box felt out of place
Problem
A background box was added around the home page title, search bar, and provider toggle buttons to create visual grouping. However, this made the area look like a separate section or card, which felt strange and broke the natural flow of the page.
Fixed
The background box was completely removed. The home page title, subtitle, search bar, and Office/Freelancer buttons are back in their clean, natural sequence — no background card, no extra border — exactly as intended in the original design.

Functional
1
Microphone / Voice Search button did not work on Replit
Problem
The voice search button on the home page was completely non-functional when the app was hosted on Replit. Replit's hosting platform forces a security rule (Permissions-Policy: microphone=()) on all pages, which blocks the browser from accessing the microphone entirely — regardless of user settings.
Fixed
A popup-based approach was implemented. When the user clicks the mic button, a small popup window opens (hosted on a separate domain, not blocked by Replit's policy). The popup captures the user's voice using the browser's speech recognition. Once the user speaks, the popup closes automatically and the spoken text appears in the search box — seamlessly and without any extra steps.
2
Browser tab title and page description were the same on all pages
Problem
Every page of the app showed the same browser tab title "SkayOffice" and the same generic description, regardless of which page the user was on. The Terms, Privacy, and Home pages all had identical tab titles — making it impossible for users or search engines to tell the pages apart.
Fixed
Each page now has its own unique browser tab title (e.g. "Terms of Use — SkayOffice", "Privacy Policy — SkayOffice"). The title and description update automatically when switching between pages, and also change when the user switches between English and Arabic language modes.

SEO & Metadata
1
Home page had no unique meta title or search keywords
Problem
The home page did not have a descriptive meta title or keywords that Google and other search engines could read. The page title was just "SkayOffice" — with no information about what the platform does or who it is for. This makes it very difficult for people to find the site through search.
Fixed
The home page now has a full set of meta tags: Title: "SkayOffice — Discover Professional Offices & Freelancers". Description explains what the platform does and where it operates. Keywords include offices, freelancers, Saudi Arabia, Riyadh, Jeddah, and related terms — in both English and Arabic depending on the selected language.
2
Terms of Use page had no meta title or description for search engines
Problem
The Terms of Use page had no unique title or description. If someone searched for "SkayOffice terms" in Google, the result would show a meaningless or auto-generated snippet — not a clear, professional description of the page.
Fixed
The Terms page now has its own meta title ("Terms of Use — SkayOffice"), a clear description about what the terms cover and who operates the platform, and relevant keywords including "terms of use", "SkayOffice", and "Future Road Labs" — in both languages.
3
Privacy Policy page had no meta title or description for search engines
Problem
Same issue as the Terms page — the Privacy Policy had no unique title or description. Search engines and browser tabs showed the generic "SkayOffice" title, giving no indication to users or search engines that this page is about data privacy.
Fixed
The Privacy Policy page now has its own meta title ("Privacy Policy — SkayOffice"), a description explaining how the platform collects and protects user data, and keywords including "privacy policy", "data protection", and "Future Road Labs" — updating automatically in Arabic when the user switches language.

Usability & User Experience — Session 2
6
Toast notification appeared in wrong position (bottom / center)
Problem
After adding toast notifications, they appeared at the bottom or center of the screen instead of the expected top-right corner. This is non-standard behaviour — almost every web application shows brief alerts in the top-right so they don't block content.
Fixed
The ToastViewport position was updated to top: 16px; right: 16px — fixed to the top-right corner of the screen. Toast messages now appear where users expect them, without blocking page content.
7
Toast close (×) button showed default cursor, not a pointer
Problem
When hovering over the dismiss (×) button on a toast notification, the mouse cursor stayed as the default arrow instead of changing to a hand/pointer. This made the button feel unclickable — users could not tell it was interactive.
Fixed
Added cursor: pointer to the ToastClose button. The hand cursor now appears on hover, clearly signalling to users that the button is clickable and will dismiss the notification.

Functional — Session 2
3
Voice popup mic still blocked on Replit production (same domain)
Problem
After implementing the popup approach for voice search, the popup was still hosted on skayoffice.replit.app — the same domain as the main app. Because Replit applies the microphone restriction to the entire domain, the popup inherited the same block and the mic still did not work.
Fixed
The voice-helper.html file was moved to GitHub Pages (vinaygoyal611994-ctrl.github.io/skyoffice/voice-helper.html), a completely different domain that is not subject to Replit's Permissions-Policy. The popup URL in the app was updated to point to GitHub Pages, with .nojekyll added to prevent Jekyll processing.
4
Office/Freelancer type not selected by default on Register page
Problem
On the office registration page, the Provider Type field (Office / Freelancer card selector) had no option selected by default. Users who submitted the form without explicitly clicking one of the cards would get a validation error — creating unnecessary friction for the majority of users who are registering as an Office.
Fixed
The form's defaultValues was updated to set providerType: 'office' so the Office card is pre-selected (highlighted) when the page loads. Users registering as Freelancers simply click the Freelancer card to switch — saving a step for the majority while remaining fully flexible.
5
Footer overlapping dashboard sidebar on office dashboard page
Problem
After registering, office users were redirected to their dashboard. The dashboard has a fixed sidebar that covers the full viewport height. The Shell footer was still being rendered beneath the dashboard, creating a layout conflict where the footer appeared behind or was partially hidden by the sidebar.
Fixed
The Shell component now checks the current route. When the user is on /office/dashboard or /admin, the footer is hidden entirely — these pages have their own full-height layouts and do not need the global footer. The footer continues to appear normally on all public pages.
6
Frontend API calls failing — Vite proxy pointing to wrong backend port
Problem
The frontend dev server (Vite) was configured to proxy /api requests to localhost:8080 by default, but the backend actually runs on localhost:3001. All API calls from the frontend silently failed, meaning login, registration, and all data fetching did not work in local development.
Fixed
The default proxy target in vite.config.ts was corrected from port 8080 to 3001. The frontend now correctly routes all API calls through the Vite dev server proxy to the running backend, so all features work without needing to set environment variables manually.
7
"Request a new link" on Forgot Password success screen did nothing
Problem
After submitting a forgot-password request, the success screen appeared with a "Request a new link" link. Clicking it navigated to the same /forgot-password route but the component was not re-mounted (same URL = no re-render in Wouter), so the form never came back and the link appeared broken.
Fixed
The link was replaced with a button that directly calls setState('idle') and clears the email field. The form instantly reappears without any navigation. This is the correct pattern — no route change needed when the reset just needs to clear local component state.
8
Header Login/Logout state not updating after login without page refresh
Problem
After a successful login or registration, the navigation header continued to show the "Login" and "Register" buttons instead of switching to "My Account" and "Logout". Only a manual page refresh would update the header to the correct logged-in state — a confusing and unprofessional experience.
Fixed
After captureSessionToken() stores the session, queryClient.invalidateQueries() is now called immediately with the getCurrentUser query key. This forces React Query to re-fetch the current user, so the header updates within milliseconds of login — no page refresh required.

Notifications & User Feedback
1
No feedback shown to user after successful customer registration
Problem
When a new customer registered successfully, the app silently redirected them to the Discover page with no message or confirmation. The user had no indication that registration worked — they were just suddenly on a different page, which felt abrupt and confusing.
Fixed
A top-right toast notification now appears: "Registration Successful! — Welcome to SkayOffice. You are now logged in." Available in both English and Arabic. The toast appears instantly after redirect so the user sees confirmation on the new page.
2
No feedback shown after office/freelancer registration
Problem
Same issue for office/freelancer registration — the user was redirected to the dashboard with no message. There was no acknowledgement that their account was created or that it would be reviewed.
Fixed
Toast notification now shows: "Office Created! — Your profile will be reviewed and verified shortly." This sets the correct expectation (approval process) while also confirming the registration succeeded.
3
No confirmation message shown after successful login
Problem
When a customer or office user logged in successfully, they were redirected with no message. There was no "Welcome back" or any other confirmation — the user had to infer they were logged in from the header change, which (before the header fix) was also broken.
Fixed
Customer login now shows: "Welcome Back! — You have successfully logged in." Office login shows: "Welcome to Your Dashboard! — Your office account has been logged in successfully." Both in English and Arabic.
4
No confirmation message shown after logout
Problem
Clicking "Logout" redirected the user to the home page silently. There was no message confirming the logout was successful — the user had to check the header to verify they were signed out, which is an extra and unnecessary step.
Fixed
A toast now appears after logout: "Logged Out — You have been successfully logged out. See you soon!" The message appears on the home page immediately after redirect, giving clear confirmation of the action.
5
No toast shown after submitting forgot-password email
Problem
After submitting the forgot-password form, only an inline success state was shown within the card. There was no brief top-level notification to acknowledge the action — just the card changing its content, which users might miss if they looked away.
Fixed
A toast notification now also appears: "Reset Link Sent — If this email is registered, a reset link has been sent to your inbox." The inline success state is still shown inside the card, and the toast provides an additional top-right confirmation.
6
No toast shown after successfully resetting password
Problem
After a successful password reset, the app showed a success card and then redirected to the login page after 3 seconds. There was no toast notification — users who looked away during the 3-second window could miss the confirmation entirely.
Fixed
A toast now fires immediately after a successful reset: "Password Changed! — You can now log in with your new password." The toast appears at the top-right and persists long enough for the user to read it before the redirect to the login page.

All 27 issues have been identified, fixed, tested locally, and pushed to GitHub. Ready for Replit deployment.
