Usability & User Experience
1
Favourite (heart) button on office card had no pointer cursor
Problem
When hovering over the heart/favourite icon on office cards, the cursor stayed as the default arrow instead of changing to a pointer. Users could not tell the button was clickable — it felt broken or decorative.
Fixed
Added cursor: pointer to the favourite heart button on QuickOfficeCard. The hand cursor now appears on hover, clearly signalling that the button is interactive and will toggle the favourite state.
2
About & Services tab buttons in office popup had no pointer cursor
Problem
The "About" and "Services" tab buttons inside the office detail popup showed an arrow cursor on hover instead of a pointer. This made it unclear that the tabs were clickable toggles, not just labels.
Fixed
Added cursor: pointer to both tab buttons in the TabBar component inside the office profile page. Both tabs now show the hand cursor on hover — consistent with standard web interaction patterns.
3
Share Office button in office popup had no pointer cursor
Problem
The "Share Office" action button in the utility grid at the bottom of the office popup showed an arrow cursor instead of a pointer, making it inconsistent with the other interactive buttons on the page.
Fixed
Added cursor: pointer to the Share Office button. The hand cursor now appears consistently on all three utility buttons — Location, Share Office, and Save Office.
4
Close (×) button on all popups/dialogs had no pointer cursor
Problem
The × dismiss button at the top-right of every dialog/popup in the app showed a default arrow cursor. This is a well-known UX anti-pattern — close buttons without a pointer cursor feel non-interactive and confuse users who expect the hand cursor.
Fixed
Added cursor: pointer to the DialogPrimitive.Close button inside the shared dialog.tsx UI component. This fix applies globally — every dialog and popup throughout the entire app now shows the correct pointer cursor on the close button.
5
Favourite office cards on Account page had unequal heights (zigzag layout)
Problem
On the Account page's Favourite Offices section, cards in the same row had different heights depending on their content. This created an uneven zigzag layout that looked unfinished and unprofessional in a two-column grid.
Fixed
Added h-full to both the outer wrapper div and the Link element inside QuickOfficeCard. Cards in the same row now always stretch to the same height — the grid stays visually balanced regardless of content differences.
🔔
Notifications & User Feedback
1
No toast shown when adding an office to favourites
Problem
When a logged-in customer clicked the heart button to add an office to favourites, the button turned red but there was no toast or message to confirm the action. Users had no feedback that the save was successful — they could easily double-tap or wonder if it worked.
Fixed
A top-right toast now appears immediately after favouriting: "Added to Favourites — Office saved to your favourites list." Available in both English and Arabic. Works from both the office card (QuickOfficeCard) and the full office profile popup.
2
No toast shown when removing an office from favourites
Problem
Similarly, when removing a saved office from favourites, there was no confirmation message. The heart just turned grey with no feedback — users could not be sure the removal was saved or whether they accidentally clicked.
Fixed
A toast now appears on removal: "Removed from Favourites — Office removed from your favourites list." Both add and remove toasts are bilingual and appear at the top-right — consistent with the rest of the app's notification system.
🎨
Design & UI Improvements
1
No favourites counter visible in the navigation header
Problem
The heart icon in the navigation header linked to the Favourites page but showed no count. Customers had no at-a-glance indication of how many offices they had saved — they had to navigate to the Favourites page to see the number.
Fixed
A rose-red badge counter now appears on the heart icon whenever the customer has one or more saved offices. The count updates automatically when offices are added or removed (React Query cache), shows on both desktop header and mobile menu, and displays 99+ for counts above 99.
2
Account page had a basic, plain card-list layout
Problem
The Account (My Account) page used a plain stacked-card layout with no visual hierarchy, no user identity area, and no quick summary of the customer's activity. It looked like a basic settings page rather than a professional profile dashboard.
Fixed
Full page redesign: a gradient hero banner at the top displays the user's initials avatar, full name, email, and account status badge. A three-column stats strip below the banner shows live counts for Favourites, Contact History, and Video Call Requests. All sections are now white rounded cards with icon section headers. Empty states have proper icons and styled dashed borders.
3
Account page was constrained to a narrow max-width instead of full screen
Problem
After the redesign, the account page content was restricted to a maximum width of max-w-3xl (~768px), leaving large empty grey areas on both sides on wider screens. This wasted screen real estate and looked unfinished on desktop.
Fixed
Removed the max-w-3xl constraint from all content sections. The page now uses the full container width — the hero banner, stats strip, and section cards all expand to use the available screen width on desktop, matching the layout of other full-width pages in the app.
4
Account page background colour did not match the app theme
Problem
The account page used a bg-muted/20 background — a slightly tinted off-white — which was visually different from the rest of the app. Other pages use bg-background, so the account page looked slightly out of place when navigating to it.
Fixed
Changed the page background from bg-muted/20 to bg-background — the same base colour used by all other pages in the app. The account page now feels visually consistent and part of the same design system.
5
Account page hero banner colour did not reflect the app's theme palette
Problem
The hero banner at the top of the account page used a flat from-primary/90 to-primary gradient — effectively a near-solid dark block. It looked flat rather than designed, and did not express the depth or richness that the rest of the app's theme implies.
Fixed
Updated the gradient to from-[hsl(215,25%,18%)] via-[hsl(215,25%,27%)] to-[hsl(215,30%,36%)] — a three-stop horizontal gradient that goes from a deep dark slate on the left to a slightly lighter slate-blue on the right. This adds natural depth and is derived directly from the theme's primary colour variable (hsl(215, 25%, 27%)).
