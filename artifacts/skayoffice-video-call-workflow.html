1. System Overview

The Video Call Booking system allows customers to request a live video consultation with any office listed on SkayOffice. When an office accepts the request, the platform automatically creates a Zoom meeting and provides both parties with the correct link to join. The office gets the host link (to start the meeting) and the customer gets the participant link (to join).

👤 Customer Side

  • Browse offices and find one offering video calls
  • Fill in preferred date, time, timezone, and contact number
  • Track request status from their account page
  • Join the Zoom meeting with one click when accepted

🏢 Office Side

  • Connect their Zoom account once (OAuth)
  • Receive incoming booking requests on the dashboard
  • Accept, decline, reschedule, or cancel bookings
  • Start Zoom meetings directly from the dashboard
🔗
Zoom Integration: The platform uses Zoom OAuth 2.0. Each office connects its own Zoom account. When a request is accepted, a Zoom meeting is automatically created — no manual scheduling needed.

2. Prerequisites & Setup

For the Office (One-time setup)

  1. Log in to Office Dashboard
    Use office email/password at the Office Portal.
  2. Enable Video Call Feature
    Go to Contact Features section → toggle on Video Call Booking.
  3. Connect Zoom Account
    Click Connect Zoom → authorise SkayOffice to manage meetings. Done once — tokens auto-refresh.

For the Customer

  1. Register / Log In
    Customer registers once at the Customer Portal with email and password.
  2. No Zoom Account Needed
    Customer joins via a standard browser or Zoom app — no Zoom account required.
Section 3

Customer Workflow — Step by Step

Everything a customer does from discovering an office to submitting their video call request.

  1. Discover an Office
    The customer opens the SkayOffice platform and browses offices using the search/filter tools (by specialty, city, language, etc.). Offices that have video call enabled show a video call option on their profile page.
  2. Open the Request Form
    On the office profile page the customer clicks "Request a Video Call". This button only appears if the office has the feature enabled and their Zoom is connected. If the customer is not logged in, they are redirected to login first, then returned to the same page.
  3. Fill in the Booking Form
    The form has the following fields:
Field Description Required?
Preferred Date The date the customer wants the call (date picker) ✅ Yes
Preferred Time Time of the call (time picker, 24-hour format) ✅ Yes
Timezone Searchable dropdown with all IANA timezones (e.g., Asia/Riyadh, Asia/Kolkata, Europe/London) ✅ Yes
Contact Number Phone number the office can reach the customer on ✅ Yes
Note Free text — the customer describes what they need help with ❌ Optional
  1. Submit the Request
    Customer clicks "Send Request". The system immediately shows a success message: "Your request was sent — the office will contact you to confirm the appointment."

    The request is logged as a contact event and counted toward the office's verified commercial contact metrics.
  2. Track the Request Status
    The customer opens their Account page → My Video Call Requests. Each request shows the current status (New, Viewed, Accepted, Declined, etc.) and updates in real time as the office responds.
  3. Wait for Acceptance
    When the office accepts the request, the status changes to Accepted and a "Join Zoom Meeting" button appears on the customer's account page. The customer can click it at any time to open the Zoom meeting link.
✅
No duplicate bookings: If a customer accidentally submits the same request twice within 60 seconds, the system detects the duplicate and returns the existing record — no extra records are created. Additionally, if the office has already accepted a request for the exact same date and time, new submissions for that slot are automatically rejected with a clear message.

Section 4 & 5

Office Workflow — Managing Requests

Everything the office does from receiving a new request to completing the call.

4. Receiving Incoming Requests

  1. Log in to the Office Dashboard
    The office user logs into the SkayOffice Office Portal. The dashboard shows all sections: Overview, Video Call Requests, Contact Events, etc.
  2. Navigate to "Video Call Requests"
    A blue notification badge on the section header shows how many New requests are waiting. Requests are listed in reverse chronological order (newest first).
  3. Review the Request
    Each request card shows:
    • Customer name and contact number
    • Preferred date, time, and timezone
    • Note (if the customer left one)
    • Date received
    • Current status badge
  4. Mark as Viewed (Optional)
    Clicking "Mark Viewed" changes the status to Viewed. This is a confirmation to the customer that the office has seen their request. It does not accept or reject it — it just acknowledges receipt.

5. Accepting a Request & Starting the Call

⚡
What happens automatically when you click Accept: The system immediately creates a Zoom meeting using the office's connected Zoom account. No manual scheduling in Zoom needed.
  1. Click "Accept"
    The office clicks the Accept button on the request card. The system:
    — Checks the slot is not already booked (double-booking guard)
    — Creates a Zoom meeting at the requested date/time/timezone
    — Saves both the host-start URL and participant join URL
    — Changes request status to Accepted
  2. The "Start Zoom Meeting" Button Appears
    After acceptance, the request card shows a "Start Zoom Meeting" button. This link uses the host-start URL which opens Zoom in host mode — meaning the office can start the session, manage participants, record, etc.
  3. At Meeting Time — Click "Start Zoom Meeting"
    When the scheduled time arrives, the office user clicks the button. Zoom opens (in browser or Zoom app). The office is the host and waits in the meeting. The customer joins from their participant link.
  4. After the Call — Mark as Completed
    Once the call ends, the office clicks "Mark Completed". The request is archived with a Completed status. This keeps the dashboard clean.

🔐 Security: Separate Links for Host and Participant

The host-start URL (which gives host control over the Zoom meeting) is never shared with the customer. The API endpoint that returns the customer's join link is structurally designed to omit the host URL — this is enforced at the server level, not just in the UI.

Section 6 & 7

Rescheduling & Cancellation

6. Rescheduling an Accepted Booking

After a booking is accepted, if the office or the customer needs to change the date or time, the office can reschedule. This updates both the SkayOffice database and the existing Zoom meeting in one operation — no need to delete and recreate anything.

📅
FR-07 — Rescheduling is a contracted requirement. The Zoom meeting is updated via the Zoom API (PATCH request), so existing join links remain valid — the meeting time simply changes. This avoids sending new links to the customer.
  1. Click "Reschedule" on an Accepted Request
    The office clicks the Reschedule button (calendar icon) on any Accepted request card. A dialog box opens.
  2. Choose New Date and Time
    The dialog pre-fills with the current date and time. The office selects the new preferred date and time. The timezone remains the same (as originally specified by the customer).
  3. Click "Confirm Reschedule"
    The system:
    — Checks the new slot is not already booked (double-booking guard)
    — Updates the request record (preferredDate, preferredTime)
    — Sends a PATCH request to Zoom API to update the meeting time
    — Updates the meeting record in the SkayOffice database
    — The dialog closes; the request card refreshes with the new time
⚠️
Important: Currently, rescheduling is initiated by the office only. If the customer wants to reschedule, they should contact the office directly (via WhatsApp or phone number on file), and the office performs the reschedule on the dashboard.

7. Cancellation Flow (After Acceptance)

When an already-accepted booking needs to be cancelled (e.g., the customer called to cancel, or the office has an emergency), the system follows a safe multi-step cancellation flow to ensure the Zoom meeting is properly deleted before the booking is marked cancelled.

🔄
FR-06 — Cancellation Pending Flow is a contracted requirement. It ensures data consistency: if Zoom cancellation fails partway, the booking stays in a visible Cancelling state rather than being silently dropped.

Automatic steps when "Cancel Booking" is clicked:

✅ Accepted
→
⏳ Cancellation Pending
→
Zoom meeting deleted via API
→
🚫 Cancelled

The entire flow happens automatically on the server in one request. The office does not need to take any additional steps.

  1. Click "Cancel Booking" on an Accepted Request
    A confirmation dialog appears: "Are you sure you want to cancel this booking? The Zoom meeting will be deleted."
  2. Confirm the Cancellation
    The office clicks OK. The system transitions the booking through Cancellation Pending, cancels the Zoom meeting, then sets the final status to Cancelled.
  3. Result
    The request card shows Cancelled (grey badge). The customer's account page also updates to show Cancelled. The Zoom meeting is deleted from the office's Zoom account.

8. Declining a New or Viewed Request

Declining applies to requests that are still in New or Viewed status — before any Zoom meeting has been created. This is different from cancellation (which applies after acceptance).

When to use "Decline"

  • Office is fully booked for that period
  • Customer's requirements don't match the office's specialty
  • Request was submitted in error

When to use "Cancel Booking"

  • Booking was already accepted (Zoom created)
  • Last-minute emergency on either side
  • Customer called to cancel after confirmation
Section 9

Customer — Joining the Zoom Call

  1. Wait for the "Accepted" Status
    The customer monitors their Account page → My Video Call Requests. When the office accepts, the status changes to Accepted and the join button appears.
  2. Click "Join Zoom Meeting"
    The customer clicks the Join Zoom Meeting button on their account page. The system fetches a secure join link from the server and opens it in a new browser tab. The customer can join via browser or the Zoom app.
  3. Wait in the Waiting Room
    The meeting has a Waiting Room enabled. The customer waits until the office (host) admits them. This prevents any participant from entering before the host is ready.
  4. The Call Takes Place
    The office and customer conduct their consultation over Zoom video. Meeting duration is set to 25 minutes by default.
🔐
Meeting Password: All Zoom meetings are created with password protection. The join link the customer receives already contains the password embedded, so they don't need to enter it manually. The raw password is never shown to the customer separately.

Section 11

Double-Booking Prevention

The platform implements FR-05 — Double-Booking Prevention as a contracted requirement. It operates at two levels:

Level 1 — Submission Guard

When a customer submits a request, the backend checks whether the same office already has an accepted or cancellation_pending booking for the exact same date and time. If yes, the request is rejected with:

🚫
"This time slot is already booked. Please choose a different date or time."

Level 2 — Accept Race-Condition Guard

When the office clicks Accept, the backend runs the slot conflict check inside a database transaction. This prevents the following race condition:

Two different customers submit for the same slot simultaneously → both pass Level 1 → office accidentally accepts both → system now detects conflict and blocks the second acceptance.

Section 12

Security & Technical Notes

Feature Implementation
OAuth Tokens Encrypted Zoom access & refresh tokens stored encrypted (AES-256-GCM) in the database. Never stored in plaintext.
Token Auto-Refresh Tokens refresh automatically when they expire (5-minute window). Concurrent refresh requests are handled safely via a conditional database lock — only one refresh runs at a time.
Meeting Password Every Zoom meeting is created with password_required: true. The password is embedded in the join link; customers never enter it manually.
Waiting Room All meetings have Zoom Waiting Room enabled. The host (office) must admit the customer — no auto-join.
Host Link Protection The host-start URL is returned only on the office-authenticated endpoint. The customer's join endpoint structurally omits it — enforced server-side.
Webhook Verification Zoom webhook events (meeting.deleted, meeting.ended) are verified using HMAC-SHA256 signatures before being processed.
Rate Limiting Submission endpoints are rate-limited: max 20 requests per minute per user, preventing abuse.
OAuth CSRF Protection Zoom OAuth flow uses an HMAC-signed state parameter to prevent cross-site request forgery attacks.
Zoom Disconnect Blocking If an office disconnects Zoom, customers cannot submit new video call requests for that office until Zoom is reconnected.
Audit Log Every status change and reschedule is recorded in the audit log with actor, timestamp, and metadata.
