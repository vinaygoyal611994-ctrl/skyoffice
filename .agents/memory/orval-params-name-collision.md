---
name: orval Params type/const name collision
description: Adding a query param to an operation that already has a path param can make orval's zod codegen and react-query codegen emit two same-named `XxxParams` exports, causing a TS2308 ambiguous re-export.
---

## What happens
For an operation with **both** a path param and a query param (e.g. `POST /offices/{officeId}/assistant/conversations?language=...`), orval's `react-query` client generates a combined `types/xxxParams.ts` TS type (`XxxParams`) for the function signature, while the `zod` client's `generated/api.ts` also exports a zod object literal named `XxxParams` for the same operation. Both get barrel-re-exported from `@workspace/api-zod`'s `src/index.ts` (`export * from "./generated/api"` + `export * from "./generated/types"`), so `tsc` reports:

```
error TS2308: Module "./generated/api" has already exported a member named 'XxxParams'.
```

Query-only operations (no path param) don't hit this, because orval names that zod const `XxxQueryParams` instead — the collision is specific to path+query combos.

## How to apply
`lib/api-zod/src/index.ts` is hand-maintained (not regenerated by orval) — it only needs `export * from "./generated/api"`. The `generated/types` folder's plain TS interfaces are not otherwise consumed anywhere in this codebase (routes import the zod consts directly), so dropping that export line resolves the collision without losing anything in practice. Re-check that assumption if a future consumer imports a name only found in `generated/types`.
