---
name: api-error-shape
description: The correct property path for reading error details from a failed api-client-react mutation/query in this codebase.
---

`customFetch` throws `ApiError`, which exposes the parsed error body directly as `err.data` (e.g. `err.data.error`, `err.data.missingFields`) — there is **no** `err.response.data`. `err.response` is the raw `Response` object (status/headers), not a parsed-body container.

**Why:** This codebase's fetch wrapper isn't axios. Code copied from axios-style examples (`err?.response?.data?.foo`) type-checks fine (both are `any`) but silently reads `undefined` at runtime, so field-specific error UI (e.g. a missing-fields banner) quietly falls back to a generic message instead of throwing or failing loudly — easy to ship unnoticed.

**How to apply:** In any `onError` handler for `useXyzMutation`/`useXyzQuery` hooks generated by orval in this repo, read `err?.data?.<field>`, not `err?.response?.data?.<field>`. Grep for `response?.data` or `response.data` when auditing error-handling code here.
