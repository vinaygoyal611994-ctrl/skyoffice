Resolved Issues
1
Office Login Redirecting to Home Page Bug
After a successful office login, users were being sent to the site's home page instead of their dashboard. The session was established correctly but navigation was landing on the wrong destination. Fixed so that office users always land on their dashboard after login.
Office Login
2
Admin Dashboard Opening on Account Settings Instead of Overview UX
When an admin logged in, the dashboard was opening on whichever section they had last visited — often Account Settings — instead of the main Command Center (Overview). Admins now always land on the Overview / Command Center immediately after login.
Admin Dashboard
3
KPI Cards Not Navigating to Relevant Sections UX
Clicking on Key Performance Indicator cards in the admin Command Center was not navigating to the corresponding management section. All cards are now clickable and take the admin directly to the relevant section — Offices, Customers, or Intelligence Hub.
Admin Command Center
4
KPI Cards with Zero Count Were Still Clickable UX
Cards showing a count of zero were still responding to clicks and navigating to sections that had no relevant records to display. Cards now only become clickable when they have data to show — a count of zero means the card is static and non-interactive.
Admin Command Center
5
Admin Logout Redirecting to Site Home Page Bug
Logging out from the admin dashboard was sending the admin to the public home page of the site. Admin logout now correctly redirects to the Admin Login page so the admin can sign back in without navigating manually.
Admin Logout
6
Raw Error Code Shown on Wrong Admin Credentials UX
When an admin entered incorrect login credentials, the system was displaying a raw technical error code such as INVALID_CREDENTIALS instead of a clear, readable message. The error display now shows a proper human-friendly message for all credential error scenarios.
Admin Login
7
Office User Able to Log In via Customer Login Portal Security
An office account could successfully authenticate through the Customer Login page, gaining access to the customer area with the wrong role. The Customer Login portal now validates the role of the account — only customer accounts are accepted, and any other role is rejected with a clear message directing them to the correct login portal.
Customer Login · Role Enforcement
8
Customer User Able to Log In via Office Login Portal Security
Similarly, a customer account could authenticate through the Office Login page. The Office Login portal now enforces role validation — only office accounts are accepted, with a clear message shown for any mismatch.
Office Login · Role Enforcement
9
Logged-in Admin Could Access the Admin Login Page UX
An admin who was already logged in could still navigate directly to the Admin Login URL and see the login form. The page now detects an active admin session and automatically redirects to the dashboard, preventing the login form from showing unnecessarily.
Admin Login · Session Guard

All 9 issues resolved and live.
